# วิธีแก้ไฟล์ .md ที่เสียหายจากการแปลงด้วย markitdown

คู่มือนี้ใช้กับไฟล์ Markdown ภาษาไทยที่ได้จากการแปลง PDF ด้วย `markitdown`
สคริปต์ที่ใช้คู่กันคือ `fix_markitdown.py` ในโฟลเดอร์เดียวกันนี้

---

## 1. อาการเสียที่พบบ่อย

| อาการ | ตัวอย่าง | สาเหตุ |
|---|---|---|
| สระอำแตกเป็นสระอา | `จ ากัด` แทน `จำกัด` | ฟอนต์ใน PDF วาดสระอำเป็นนิคหิต + สระอา คนละตำแหน่ง ตัวแยกข้อความจึงอ่านเป็นคนละอักขระ |
| วรรณยุกต์/สระหลุดไปต้นบรรทัด | `่เลม` แทน `เล่ม` | เหตุผลเดียวกัน แต่หลุดข้ามบรรทัด |
| หัวกระดาษปนในเนื้อหา | `เล่ม ๑๓๖ ตอนที่ ๖๙ ก ... ราชกิจจานุเบกษา` โผล่ทุกหน้า | markitdown ดึงข้อความทุกชิ้นในหน้า รวมหัว/ท้ายกระดาษและเลขหน้า |
| บรรทัดถูกตัดกลางประโยค | ย่อหน้าเดียวกลายเป็นหลายบรรทัด | การขึ้นบรรทัดใน PDF คือการจัดหน้า ไม่ใช่การขึ้นย่อหน้า |
| ทั้งหน้าอยู่ในบรรทัดเดียว | บรรทัดยาว 2,000–6,000 ตัวอักษร | PDF บางไฟล์เก็บข้อความทั้งบล็อกเป็นชิ้นเดียว |
| ไม่มีหัวข้อ Markdown | ไม่มี `#` เลยทั้งไฟล์ | markitdown อาศัยขนาดฟอนต์ในการเดาหัวข้อ ซึ่งมักใช้กับเอกสารไทยไม่ได้ |
| ช่องว่างซ้ำ | `พ.ศ.  ๒๕๖๒` | PDF ใช้ระยะห่างจัดคอลัมน์ ไม่ใช่เว้นวรรคจริง |
| CRLF / BOM | — | ไฟล์ที่สร้างบน Windows |

> **จุดสำคัญ:** ช่องว่างซ้ำดูเหมือนขยะ แต่เป็นร่องรอยโครงสร้างที่มีค่าที่สุดในไฟล์
> ห้ามยุบช่องว่างก่อนสร้างหัวข้อ มิฉะนั้นจะไม่มีทางรู้ว่าชื่อหัวข้อจบตรงไหน

## 2. หลักการซ่อม

ลำดับขั้นตอนสำคัญมาก ห้ามสลับ

```
1. ทำความสะอาดอักขระ   → BOM, CRLF, no-break space, form feed
2. ซ่อมสระอำ            → '<พยัญชนะ> า' เป็น 'ำ'
3. ลบหัว/ท้ายกระดาษ     → หาบรรทัดที่ซ้ำทุกหน้า
4. รวมบรรทัดเป็นย่อหน้า  → reflow
5. สร้างหัวข้อ + รายการ  → ใช้ช่องว่างซ้ำเป็นตัวชี้ขอบเขต  ◄ ต้องทำก่อนข้อ 6
6. ยุบช่องว่างซ้ำ
7. ตรวจว่าอักษรไม่หาย    → เทียบตัวอักษรก่อน/หลัง
```

### 2.1 ซ่อมสระอำ

```python
re.sub(r"([\u0E01-\u0E2E][\u0E48-\u0E4B]?) า", r"\1\u0E33", text)
```

แปลว่า "พยัญชนะไทย + วรรณยุกต์ (ถ้ามี) + เว้นวรรค + สระอา" ให้กลายเป็น "พยัญชนะ + สระอำ"
ต้องมีเงื่อนไขพยัญชนะนำหน้า มิฉะนั้นจะไปแก้คำที่ขึ้นต้นด้วย "อา" ที่ถูกต้องอยู่แล้ว เช่น "ใน อาคาร"

### 2.2 ลบหัว/ท้ายกระดาษ

อย่าเขียน regex เจาะจงข้อความ เพราะเลขหน้าเปลี่ยนทุกหน้า
วิธีที่ใช้ได้กับทุกไฟล์คือ **แทนตัวเลขทุกตัวด้วย `#` แล้วนับบรรทัดซ้ำ**
บรรทัดใดสั้นกว่า 60 ตัวอักษรและซ้ำตั้งแต่ 3 ครั้งขึ้นไป ให้ถือว่าเป็นหัว/ท้ายกระดาษ

ตรวจก่อนลบเสมอ ด้วยการรันสคริปต์โดยไม่ใส่ `-o` แล้วดูรายการที่จะถูกลบ

### 2.3 สร้างหัวข้อ

ใช้กติกา 2 ข้อที่ markitdown ทิ้งร่องรอยไว้ (ยืนยันกับ พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคลแล้ว)

1. **เลขหัวข้อจริงตามด้วยช่องว่าง 1 ช่อง ส่วนการอ้างอิงตามด้วย 2 ช่อง**
   `มาตรา ๘ ให้มี...` คือหัวข้อ แต่ `ตามมาตรา  ๘  วรรคสอง` คือการอ้างอิง
   กติกานี้แยกหัวข้อจริง 96 มาตราออกจากการอ้างอิง 116 จุดได้ถูกต้องทั้งหมด
2. **ชื่อหัวข้อจบเมื่อเจอช่องว่าง 3 ช่องขึ้นไป**
   `หมวด  ๑ คณะกรรมการคุ้มครองข้อมูลส่วนบุคคล   มาตรา ๘ ...`

ระดับหัวข้อที่ใช้ (โปรไฟล์ `law`)

| ระดับ | ใช้กับ |
|---|---|
| `#` | ชื่อเอกสาร (ใส่เองด้วย `--title`) |
| `##` | ภาค / ลักษณะ / หมวด / บทเฉพาะกาล |
| `###` | ส่วนที่ |
| `####` | มาตรา |

โปรไฟล์ `book` ใช้ `#` ภาค, `##` บทที่, `###` ตอนที่, `####` ข้อ

### 2.4 ตรวจว่าเนื้อหาไม่หาย

ขั้นตอนนี้ห้ามข้าม ตัดอักขระที่ไม่ใช่ตัวอักษรออกทั้งหมด แล้วเทียบสตริงก่อนกับหลัง
ถ้าไม่ตรง แปลว่า regex กลืนเนื้อหาไปบางส่วน สคริปต์จะไม่เขียนไฟล์และรายงานจุดที่ต่างกัน

## 3. แปลงทั้งโฟลเดอร์ในครั้งเดียว

ถ้ามี PDF หลายไฟล์ (เช่นไฟล์ที่ถูกตัดแบ่งเป็น `07_pages_11-40.pdf`) ใช้ `batch_markitdown.py`
แทนการพิมพ์คำสั่ง markitdown ทีละไฟล์

```bat
REM ดูรายการไฟล์ก่อน ยังไม่แปลง
python batch_markitdown.py D:\DATA\Download\IDM\Compressed\pdf_split --dry-run

REM แปลงทั้งโฟลเดอร์ แล้วซ่อมต่อทันทีในขั้นตอนเดียว
python batch_markitdown.py D:\DATA\Download\IDM\Compressed\pdf_split --fix
```

| ตัวเลือก | ความหมาย |
|---|---|
| `-o DIR` | แยกโฟลเดอร์ผลลัพธ์ (ค่าเริ่มต้นวางไว้ที่เดิม) |
| `--ext .pdf .docx` | เลือกนามสกุลที่จะแปลง |
| `-r` | ไล่โฟลเดอร์ย่อยด้วย |
| `--fix` | เรียก `fix_markitdown.py` ซ่อมต่อทันที |
| `--overwrite` | เขียนทับ .md เดิม (ค่าเริ่มต้นคือข้าม) |
| `--workers 4` | แปลงพร้อมกันหลายไฟล์ |
| `--dry-run` | แสดงรายการไฟล์อย่างเดียว |

เรียงไฟล์แบบธรรมชาติ (`02` มาก่อน `10`) ข้ามไฟล์ที่แปลงไว้แล้ว และถ้ามีไฟล์ผิดพลาด
จะบันทึกรายชื่อไว้ที่ `_markitdown_errors.log` ในโฟลเดอร์ผลลัพธ์

> ถ้าไฟล์ไหนได้ข้อความสั้นผิดปกติ สคริปต์จะเตือนว่าน่าจะเป็น PDF สแกนที่ต้อง OCR ก่อน

## 4. วิธีใช้สคริปต์ซ่อมแยกต่างหาก

```bat
cd D:\claude.ai\content-hub\_source

REM ตรวจอย่างเดียว ยังไม่เขียนไฟล์ - ทำขั้นนี้ก่อนเสมอ
python fix_markitdown.py book\pdpa.md

REM ซ่อมแล้วบันทึกเป็นไฟล์ใหม่ (อย่าเขียนทับต้นฉบับ)
python fix_markitdown.py book\pdpa.md -o book\pdpa.clean.md --title "พระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล พ.ศ. ๒๕๖๒"
```

ตัวเลือก

| ตัวเลือก | ความหมาย |
|---|---|
| `-o FILE` | ไฟล์ผลลัพธ์ ถ้าไม่ใส่จะตรวจอย่างเดียว |
| `--profile law\|book\|none\|auto` | ชุดรูปแบบหัวข้อ ค่าเริ่มต้น `auto` (นับคำว่า "มาตรา" กับ "บทที่" แล้วเดาให้) |
| `--title "..."` | ใส่บรรทัด `#` ไว้บนสุด |
| `--no-reflow` | ไม่รวมบรรทัด ใช้เมื่อไฟล์ต้นทางแบ่งย่อหน้ามาถูกแล้ว |
| `--no-headings` | ไม่สร้างหัวข้อ ใช้เมื่อจะจัดหัวข้อเอง |
| `--keep-spaces` | ไม่ยุบช่องว่างซ้ำ ใช้เมื่อยังต้องวิเคราะห์โครงสร้างต่อ |
| `--lines` | คงทุกบรรทัดเดิม เพิ่มแค่เครื่องหมาย Markdown (`#` บทที่/หัวข้อ 1.1, บรรทัดว่างก่อนรายการและตาราง, `\` กันเลขรายการถูกเรียงใหม่) แล้วตรวจว่าถอดเครื่องหมายออกได้บรรทัดตรงต้นฉบับทุกบรรทัด เหมาะกับหนังสือที่จัดหน้าหลายคอลัมน์ |

ตัวอย่างผลลัพธ์ที่ผ่าน

```
## ผลการซ่อม
  ลบหัว/ท้ายกระดาษ : 220 บรรทัด
  รูปแบบหัวข้อ      : law
  ตรวจความครบถ้วน  : ผ่าน อักษรทั้งหมดตรงกับต้นฉบับ (76458 ตัว)
  บันทึกแล้ว        : book\pdpa.clean.md (80761 อักขระ)
```

## 5. ตรวจงานด้วยตา

หลังสคริปต์ทำงานผ่านแล้ว ให้สุ่มตรวจ 5 จุดนี้

1. **หัวข้อครบหรือไม่** — `findstr /b "#" book\pdpa.clean.md` แล้วนับจำนวนหัวข้อเทียบกับสารบัญใน PDF
2. **ต้นไฟล์และท้ายไฟล์** — ส่วนปกและภาคผนวกมักมีรูปแบบต่างจากเนื้อหาหลัก จึงพลาดบ่อยที่สุด
3. **คำที่มีสระอำ** — ค้นหา `" า"` (เว้นวรรคแล้วตามด้วยสระอา) ต้องไม่เหลือเลย
4. **ตาราง** — markitdown แปลงตารางใน PDF ได้แย่มาก ตารางมักกลายเป็นข้อความเรียงกันจนอ่านไม่รู้เรื่อง ต้องพิมพ์ใหม่เอง
5. **รูปภาพ** — ข้อความในรูปหายไปทั้งหมด ถ้าเนื้อหาสำคัญอยู่ในแผนภาพ ต้องเปิด PDF ดูเทียบ

## 6. ข้อจำกัดที่สคริปต์แก้ให้ไม่ได้

- **การแบ่งวรรคภายในมาตรา** ตอนแปลงจาก PDF ตัวแบ่งวรรคกลายเป็นช่องว่างธรรมดา ซึ่งแยกไม่ออกจากการขึ้นบรรทัดใหม่ในหน้ากระดาษ ผลคือหลายวรรคจะรวมอยู่ในย่อหน้าเดียว ถ้าต้องการความถูกต้องระดับวรรค ต้องเทียบกับตัวบทจากแหล่งทางการแล้วแก้ด้วยมือ
- **ตารางและแผนภาพ** ต้องสร้างใหม่
- **เชิงอรรถ** มักถูกดึงมาปนท้ายหน้า ต้องย้ายเอง
- **PDF สแกน** ที่ไม่มีชั้นข้อความ markitdown จะได้ไฟล์ว่าง ต้องทำ OCR ก่อน (เช่น `ocrmypdf --language tha`)

## 7. ทางเลือกอื่นแทน markitdown

ถ้าไฟล์ผลลัพธ์เสียหายหนักจนซ่อมไม่คุ้ม ให้ลองเครื่องมืออื่นตั้งแต่ขั้นแปลง

| เครื่องมือ | เหมาะกับ | หมายเหตุ |
|---|---|---|
| `pdftotext -layout` (poppler) | เอกสารคอลัมน์เดียว | เร็ว รักษาการจัดหน้า และไม่ทำสระอำแตก |
| `pymupdf4llm` | เอกสารทั่วไป | ได้ Markdown พร้อมหัวข้อ คุณภาพดีกว่า markitdown ในภาษาไทย |
| `marker` | เอกสารมีตารางและสูตร | ช้าและกินทรัพยากรมาก แต่แปลงตารางได้ดีที่สุด |

แนะนำให้ลอง `pymupdf4llm` เป็นอันดับแรกสำหรับเอกสารไทย เพราะปัญหาสระอำแตกมักไม่เกิด
